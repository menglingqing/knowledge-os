# 品牌到 UI：人本研究型科技视觉系统

这是一套从品牌语义推导到界面、图形与跨媒介应用的视觉决策方法。它不是某个品牌的复刻模板，而是从研究型科技品牌参考中抽取出的关系逻辑。

核心原则：**学语法，不抄词汇。**

<a id="semantic-chain"></a>
## 1. 从品牌语义到视觉系统

不要从“选颜色、选字体、做按钮”开始。先确定品牌希望被怎样理解，再把语义翻译成视觉对比。

```text
Brand Semantics
→ Visual Contrasts
→ Foundation Tokens
→ Component Grammar
→ Cross-medium Adaptation
```

五层含义：

1. **Brand Semantics｜品牌语义**：可靠、克制、研究导向、人本、开放等。
2. **Visual Contrasts｜视觉对比**：理性 / 温度、抽象 / 人、秩序 / 材质。
3. **Foundation Tokens｜基础令牌**：颜色、字号、间距、栅格、圆角、线宽、阴影。
4. **Component Grammar｜组件语法**：按钮、输入、卡片、导航、数据与状态怎样共享同一视觉性格。
5. **Cross-medium Adaptation｜跨媒介适配**：网站、移动端、社交、包装、海报等保持同一 DNA，但不复制同一版式。

<a id="core-tension"></a>
## 2. 核心张力：理性结构 × 人的温度

研究型科技品牌容易走向两端：一端是冷硬、霓虹、赛博化；另一端是过度生活方式化，失去技术可信度。

更稳定的中间解法是：

```text
Rational Structure
× Human Warmth
× Restrained Accent
× Cross-medium Consistency
```

### 理性结构负责“可信”

- 严格栅格与稳定对齐。
- 中性、清晰的 grotesk / neo-grotesk 字体骨架。
- 克制的图标、线条、边框和信息层级。
- 数据与交互状态遵循明确规则。

### 人的温度负责“可亲近”

- 暖白、土色、石材、纸张、织物等物理感。
- 人物、自然、建筑等现实世界影像。
- 柔和但不甜腻的暖色强调。
- 允许轻微纹理、阴影、反射与深度。

结论不是“科技 + 米色”，而是：**用理性保证可信，用材质和现实世界保证人性。**

<a id="color-system"></a>
## 3. 色彩：角色先于色值

不要把一组 Hex 当成风格本身。先定义颜色角色：

| 角色 | 任务 | 使用原则 |
| --- | --- | --- |
| Ink / Text | 正文、标题、结构线 | 高对比、稳定 |
| Background | 大面积底色 | 低刺激、承载内容 |
| Surface | 卡片、分区、浮层 | 与背景形成轻微层级 |
| Accent / Action | CTA、选中、注意力 | 面积小、权重高 |
| Support | 辅助信息、图表、图形 | 低饱和、不抢主任务 |
| Semantic | 成功、警告、错误、信息 | 独立于品牌强调色 |

默认关系：中性底承载大部分内容，深色建立阅读层级，品牌色集中在关键行动或少数识别锚点。用任务优先级判断视觉权重，不固定套用面积百分比；营销 Hero 和高密度数据页可以有不同色彩分配。

### 不可直接照搬

- 不把精确色值直接认定为品牌身份；允许按项目需要选用候选色，但须验证角色、辨识度与可读性。
- 不用浅暖色承担小字号正文，除非对比度经过验证。
- 不让“品牌色”同时承担成功、错误、警告等语义状态。

## 4. 字体：复制性格，不复制字体名

字体系统应抽取以下属性：

- 中性但不机械。
- 大标题有编辑感，正文有产品可读性。
- 字重和字号层级清晰，而不是依靠花哨字形。
- 拉丁字体与中文字体分别选择，再做字面高度、字重和行高协调。

建议起点：

- Display：48/56
- H2：32/40
- H3：24/32
- Body：16/24
- Caption：12/16

这些是参考尺度，不是强制规格。真实产品还要针对桌面、移动端、中文密度与无障碍设置响应式字号。

## 5. 栅格与间距：用模数建立秩序

适合内容型、研究型网站的基础结构：

- 桌面端可从 **12 栏栅格**起步。
- 页面外边距与 gutter 分离定义。
- 间距采用有限模数，如：4 / 8 / 16 / 24 / 32 / 48 / 64 / 80 / 96。
- 不为每一个局部发明新的间距值。

价值不在“12 栏”本身，而在于：**跨页面、跨组件的空间节奏能被复用。**

## 6. 组件语法：安静，但必须完整

营销视觉可以克制，产品交互不能省略状态。

按钮、输入框、卡片、导航至少定义：

- Default
- Hover
- Active / Pressed
- Focus
- Disabled
- Error / Validation（适用时）
- Loading（适用时）

视觉建议：

- 同一个任务区域优先突出一个主行动；多区域页面不机械限制只能出现一个主按钮。
- 次按钮通过边框、文字或弱底色降级。
- 阴影只用于表达层级，不作为装饰。
- 圆角、线宽、图标笔画要统一。
- 高密度数据界面可采用更紧凑的 spacing variant，不能照搬营销页的宽松留白。

## 7. 影像与材质：把抽象智能拉回现实

适合“人本研究型科技”的视觉资产可以来自：

- 建筑：秩序、结构、尺度。
- 自然：时间、复杂系统、非人工感。
- 人物：责任、关系、真实使用者。
- 石材、纸、陶、织物：触觉和物质性。
- 抽象线条、波纹、点阵：表达网络、信息、模型、流动。

关键是形成**同一视觉家族**。不要把“建筑照片 + 3D 渐变 + 赛博霓虹 + 手绘插画”无规则混用。

## 8. 专属视觉锚点：避免“温暖 AI 品牌”同质化

暖白 + 土色 + 极简无衬线正在成为常见科技品牌语汇。仅依赖这套表面特征，容易失去识别度。

至少建立一个可拥有的视觉锚点：

- 专属几何母题。
- 独特线条生成规则。
- 独家摄影构图逻辑。
- 特定材质组合。
- 自有数据可视化语言。
- 可持续演化的图形系统。

判断标准：去掉 Logo 后，画面是否仍能被识别为同一个品牌系统。

<a id="cross-medium"></a>
## 9. 跨媒介：统一的是 DNA，不是版式

网站、移动端、包装、社交和广告不应机械复刻同一构图。

应保持稳定的是：

- 色彩角色。
- 字体层级。
- 栅格逻辑。
- 图标与线条语法。
- 图像选择原则。
- 专属视觉锚点。
- 信息语气与密度。

可变化的是：

- 构图。
- 信息量。
- 尺度。
- 动效。
- 交互方式。

## 10. 取其精华，去其糟粕

| 保留 | 不直接继承 |
| --- | --- |
| 品牌语义先于视觉表面 | Logo、字标、品牌专属图形 |
| 理性结构 × 人的温度 | 未验证便全盘照搬色值 |
| 中性底 + 小面积强调色 | 把暖色当作所有文字/状态色 |
| 编辑排版 × 产品可用性 | 指定某一商业字体为唯一答案 |
| 栅格与 spacing token | 每个媒介复制同一版式 |
| 现实材质与人物语境 | 为“高级”而滥用纹理和阴影 |
| 跨媒介视觉 DNA | 只有 moodboard，没有交互状态 |
| 克制组件语言 | 忽略可访问性、响应式和数据密度 |

## 11. 产品级补全清单

一张品牌/UI 规范板通常只展示“长什么样”，真正落地还需要补充：

- [ ] WCAG 对比度检查。
- [ ] Hover / Focus / Active / Disabled。
- [ ] Success / Warning / Error / Info。
- [ ] 深色模式（需要时）。
- [ ] 响应式断点与移动端规则。
- [ ] 中文字体和中英混排。
- [ ] 数据可视化语义色。
- [ ] 密度模式。
- [ ] 动效原则与时长曲线。
- [ ] Design token 命名与代码映射。
- [ ] 品牌资产授权与字体许可。

## 12. 快速判断公式

当我们以后分析或设计一个科技品牌 UI，可以先问四个问题：

1. **语义**：品牌想让人相信什么？
2. **张力**：画面靠哪两组相反力量建立辨识度？
3. **系统**：颜色、字体、栅格、组件是否被 token 化？
4. **迁移**：换到移动端、海报或包装，DNA 是否仍然成立？

如果只能回答“它用了什么颜色、什么字体”，说明还停留在风格表面。

<a id="implementation-baseline"></a>
## 13. 我们的默认执行约定：把风格转成可用界面

本节是本次提出的起点，不是官方规范或经实测的产品设计系统。适合内容、学习、研究、AI 助手等希望表达安静、可靠、可亲近的界面。高密度运营系统、强娱乐产品及强警示场景按任务调整。

### 13.1 配色分三层：原始值、语义角色、组件用途

例如：`palette.terracotta.700 → color.action.default → button.primary.background`。这样可保留品牌气质，又能单独修正按钮、正文与焦点的可用性。

| 建议语义 token | 候选值 | 用法 / 限制 |
| --- | --- | --- |
| `color.canvas` | `#F5F2ED` | 暖白底；来自参考板标注 |
| `color.surface` | `#F0EDE9` | 分区底，不依赖这点色差识别输入框 |
| `color.text.primary` | `#1A1A1A` | 标题与正文 |
| `color.text.secondary` | `#5C574F` | 本次修正：暖白底约 6.42:1 |
| `color.brand.decorative` | `#D97757` | 图形、装饰；普通小字不直接使用 |
| `color.action.default` | `#B05236` | 本次修正：配白色按钮字约 5.11:1 |
| `color.action.hover` / `pressed` | `#8F402A` | 本次候选：配白字约 7.16:1；按组件需要进一步区分状态 |
| `color.text.onAction` | `#FFFFFF` | 仅针对已验证 action 背景 |
| `color.border.decorative` | `#D8D0C4` | 弱分隔，不作为输入框唯一边界 |
| `color.border.control` | `#8C8579` | 暖白底约 3.27:1；换 surface 仍需复查 |
| `color.focus` | `#1A1A1A` | 建议 2px 轮廓与 2px 间隔，适用于此浅色主题；深色模式另定义 |

品牌色可以与某个状态色接近，重点是避免语义冲突：错误、警告、成功、信息各有 token、图标与文字，不靠颜色独自传意。以上是候选配对，不是整套无障碍认证；计算见[案例复核](../cases/2026-10-05-anthropic-style-brand-ui-system.md#contrast-check)。

### 13.2 版式、字体与材质的职责

- **空间与构图**：桌面 12 栏、移动端 4 栏可作起点；窄屏外边距 16–24px、桌面 gutter 24px 是建议值。断点由内容溢出与阅读负担决定，不能把海报等比缩小。间距先用 4/8/16/24/32/48/64，再按任务调整。
- **光线与氛围**：暖感优先来自底色和真实影像；阴影用于浮层、层级或拖拽反馈。品牌图可有质感与光线，操作区保持平静。
- **色彩与质感**：强调色服务行动或识别；纸、石、陶用于封面和品牌区，正文、输入、图表区保持清楚。无需每页放齐所有材质。
- **限制与规则**：中文字面、行高、换行与按钮长度独立检查。正文可从 16px / 26–28px 起步，说明文字默认 14px；12px 只用于短、非关键说明。大标题随窄屏缩小，不机械继承图上的 48/56。

字体先按语言覆盖、字面气质、加载成本与项目许可筛选；保持字体回退方案。Neue Haas Grotesk、Poppins、Lora 都不因“参考图好看”而成为唯一答案。中文长文、数据表和营销标题可以有不同排版任务。

### 13.3 组件最小状态约定

| 状态 | 建议处理 | 要解决的问题 |
| --- | --- | --- |
| Default | 明确主要与次要行动 | 读得懂、找得到 |
| Hover / Pressed | 色阶或边框反馈；触屏另有按压反馈 | 确认交互响应 |
| Focus-visible | 清晰、无遮挡的轮廓，不删去默认焦点而不补替代 | 键盘定位 |
| Disabled | 视觉降级与语义禁用一致；需要时解释原因 | 理解为何不可用 |
| Loading | 进度 / 状态文字，避免重复提交 | 知道系统在处理 |
| Error / Validation | 文字 + 图标 + 相关字段定位 | 理解问题并修正 |
| Selected / Success | 文字或形状标记配合色彩 | 不仅靠颜色识别状态 |

重要触控按钮建议至少 44px 高，这是本次舒适性建议。WCAG 2.2 AA 的目标尺寸条款是至少 24×24 CSS px，并有间距、行内等例外，**不能把 44px 建议写成 AA 必须值**。小图标可保留较小视觉尺寸，同时扩大点击区域。

### 13.4 Agent 后续调用约定

> 先写清用户任务和品牌想传达的性格，再定义中性底、文字、行动、状态色的分工。对适合安静可信气质的界面，可尝试暖白、深色信息、小面积陶土强调。正文和按钮必须验证实际前景 / 背景配对；补齐焦点、禁用、加载、错误和选中状态。中文、移动端和数据密度分别适配。借鉴关系逻辑，使用自己的品牌符号与素材，避免全盘复制参考板。

这是一条任务相关的默认方案，不把所有后续项目固定成米白与橙色；UI 决策仍围绕任务、信息与交互，不套用视觉生成的七层架构。

## 14. 验证与反例

- 内容页与高密度表格分别做一次任务检验，观察阅读、定位与操作是否清楚。
- 尝试另一组品牌强调色，看语义角色与层级是否仍成立；颜色可变而职责稳定，才说明迁移了方法。
- 使用灰阶、键盘与窄屏检查：必要信息若只靠橙色或轻边框才看得懂，需要调整。
- 暖材质若妨碍数据阅读，应缩小或移出功能区；增加纹理并不自动增加可信度。
- 至少 3 个独立案例是现有治理的必要条件；整体方法晋升仍由人类裁决。纯色计算验证只覆盖具体配对。
